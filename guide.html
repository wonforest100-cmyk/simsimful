국비 교부신청서 작성기 · 서버 설정 안내

처음 한 번만 하면 됩니다. 아래 순서대로 따라 하면 팀원 누구나 인터넷 주소로 작성기를 열고, 같은 자료를 함께 쓰게 됩니다. 걸리는 시간은 30분 정도입니다.

Supabase·GitHub 화면은 이해를 돕기 위해 본뜬 그림이라, 실제 화면과 배치나 메뉴 이름이 조금 다를 수 있습니다. 작성기 화면(10단계)은 실제 스크린샷입니다.

9

지금까지 PC에서 쓴 자료 옮기기

기존 작성기 파일 → 새 주소

브라우저는 PC에서 연 파일과 인터넷 주소의 저장 공간을 따로 씁니다. 그래서 새 주소에서는 처음에 샘플 자료만 보입니다. 이미 입력한 자료가 있으면 먼저 옮기세요.

  1. 지금까지 쓰던 작성기 파일을 열고 맨 위 백업(JSON)을 눌러 파일을 받습니다.
  2. 새 주소(https://아이디.github.io/gukbi-app/)를 엽니다. 서버 연결 화면이 나오면 서버 없이 이 PC에서만 쓰기를 잠깐 누릅니다.
  3. 맨 위 복원을 눌러 1번에서 받은 파일을 고릅니다. 자료가 보이면 다음 단계로 갑니다.
10

작성기에서 서버 연결하고 회원가입

새 주소 · 실제 화면
  1. 맨 위 이 PC에만 저장 버튼(또는 신청 기록 탭의 서버 연결하기)을 누르면 서버 연결 화면이 나옵니다. 3단계의 두 값을 넣고 저장하고 연결을 누릅니다.
  2. 회원가입 탭에서 이름, 2단계 SQL에 넣은 관리자 이메일, 비밀번호(8자 이상)를 넣고 가입하기를 누릅니다.
  3. 받은 메일의 인증 링크를 누르면 작성기로 돌아옵니다. 로그인 탭에서 로그인합니다.
  4. 처음 연결하면 어떤 자료를 쓸지 묻습니다. 9단계에서 옮긴 자료를 쓰려면 이 PC 자료로 서버 덮어쓰기를 누릅니다. 서버가 비어 있으면 이 질문 없이 바로 올라갑니다.
  5. 맨 위 표시가 서버: 동기화됨으로 바뀌면 끝입니다.

로그인 화면은 Esc를 눌러도 닫히지 않습니다. 로그인해야만 작성기를 쓸 수 있습니다.

11

팀원 초대와 회원 관리

작성기 › 신청 기록 › 회원 관리
  1. 팀원에게 작성기 주소를 알려 줍니다. 팀원은 회원가입 → 메일 인증 → 로그인만 하면 바로 같은 자료를 봅니다.
  2. 팀원마다 서버 주소와 키를 넣기 번거로우면, index.html의 const CLOUD_DEFAULT = {url: '', key: ''}; 따옴표 안에 3단계 값을 넣어 다시 올리세요. 그러면 서버 연결 화면 없이 바로 로그인 화면이 나옵니다. Publishable key는 공개되어도 되는 키입니다.
  3. 관리자는 신청 기록 › 서버 동기화 › 회원 관리에서 회원을 보고, 필요하면 사용 막기, 권한을 관리자로 바꾸기, 명단에서 빼기를 할 수 있습니다.

문제가 생겼을 때

‘서버 연결 도구를 불러오지 못했습니다’인터넷 연결이 끊겼거나 기관 방화벽이 cdn.jsdelivr.net을 막고 있습니다. 자료는 브라우저에 계속 저장되니 연결된 뒤 새로고침하세요.
인증 메일이나 비밀번호 재설정 메일이 안 옴스팸함을 확인하세요. 기본 메일은 시간당 보낼 수 있는 수가 적어 잠시 뒤 다시 시도해야 할 수 있습니다(6단계 SMTP 참고). 메일 링크가 작성기로 돌아오지 않으면 6단계 Site URL과 Redirect URLs를 확인하세요.
‘회원 명단에 없는 계정입니다’2단계 SQL을 실행하기 전에 가입한 계정입니다. 2단계 SQL을 다시 실행하거나, SQL Editor에서 insert into public.app_members (email, approved) values (lower('그 이메일'), true);를 실행하세요.
‘서버: 확인 필요’다른 사람이 먼저 저장한 내용과 겹쳤습니다. 신청 기록 탭에서 어느 쪽을 쓸지 고르세요. 버리는 쪽은 백업 파일로 받아지고, 서버의 이전 자료는 버전 기록에 남습니다.
Supabase 프로젝트가 Paused로 바뀜대시보드에서 Restore project를 누르고, 8단계 작업이 초록색으로 돌고 있는지 확인하세요. Actions가 꺼져 있으면 Actions 탭 위쪽의 Enable workflow를 누릅니다.
잘못 고쳐서 예전으로 돌리고 싶음신청 기록 › 서버 동기화 › 버전 기록에서 원하는 시점의 되돌리기를 누르세요. 최근 300번의 저장 시점이 남아 있습니다.
